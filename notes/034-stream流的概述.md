# P34 stream 流的概述

## 编辑窗口里的内容什么时候进了文件

讲师在 Windows 桌面新建 `123.txt`，用记事本对同一文件做了两次比较。

1. 输入一些文字后，标签旁出现未保存的圆点。约 02:38，关闭并选择“不保存”；再打开同一路径，正文为空。
2. 再次输入文字，在“文件”菜单中选“保存”（也可按 Ctrl+S），圆点消失。关闭窗口后从桌面重新打开 `123.txt`，约 03:08 看到了刚才输入的内容。这验证了内容可以从该文件重新读出。讲师提到关机后仍可保留，本节没有做关机测试，也没有观察操作系统何时把数据写到物理介质。

课堂使用记事本 11.2312.18.0，在右上角设置中展示了“记事本启动时”的选项。支持恢复上次会话的版本可能在重开应用后还原未保存的标签。要判断原文件是否已写入，应查看该路径下的文件内容；仅看到恢复的标签不足以确定。微软也明确区分了保存会话与保存文件（2026-11-24 核实）。[微软关于记事本会话恢复的说明](https://blogs.windows.com/windows-insider/2023/08/31/new-updates-for-snipping-tool-and-notepad-for-windows-insiders/)

## 用数据的来源和去向区分流

流让程序按顺序接收或发出数据。C 标准 I/O 用 `FILE *` 标识供库函数操作的流，程序读普通文件时可以把文件作为来源，写普通文件时可以把它作为目的地。讲师在记事本列举了六类使用场景，后续课程聚焦文件读写。[Microsoft Learn：流 I/O](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/stream-i-o?view=msvc-170)

| 场景 | 从哪里读、向哪里写 |
| --- | --- |
| 文件 | 从 `123.txt` 读回已保存的字节，或把程序产生的内容写入这个文件 |
| 标准 I/O | `stdin` 提供输入，`stdout` 接收正常输出，`stderr` 接收诊断信息。后两者可以都显示在同一终端，也可以分开重定向 |
| 管道 | 一个进程的输出交给另一个进程作为输入；画面举出 `popen` |
| 内存 | 用流接口在一块内存缓冲区中读写；画面列举 POSIX 的 `fmemopen` |
| 网络 | 通信两端通过套接字传递数据；课堂用游戏状态同步作例子 |
| 设备 | 把数据送给设备，如向打印机发送打印内容 |

管道、套接字和设备的具体接口由运行环境提供。不能仅凭“流”这个称呼，就把套接字等任何平台资源直接当作 `FILE *` 传给 C 库函数。后半节展示了这些名称和用途，没有编译或运行相应程序。
