# P82 再谈头文件与编译

头文件像一张索引卡：调用者可以从中看到有哪些类型、函数怎样调用。以事件模块为例，其他源文件需要知道事件类型和注册函数的参数；怎样存放处理函数、注册时怎样查表，可以留在模块的 `.c` 文件中。

| 课堂讨论的四个作用 | 编写项目时怎样判断 |
| --- | --- |
| 组织性 | 把同一模块对外提供的类型和函数声明放在同一个头文件。只有模块自己用的细节留在实现文件里。 |
| 重用性 | 使用模块的多个源文件包含同一份头文件。若把模块带到另一个项目，除头文件外，还需让含函数定义的源文件参与编译，或链接提供实现的库。 |
| 编译效率 | 一般先分别编译各源文件，再链接目标文件。只改某个 `.c` 的函数体时，增量构建通常可复用其他目标文件；若改的是公共头文件，直接或间接包含它的源文件通常也需要重编。具体重建范围由构建工具的依赖跟踪决定。 |
| 避免重复包含 | 同一个源文件可能直接、间接地包含同一个头文件。用包含保护让定义在本次编译单元中只展开一次，其他源文件仍然可以包含该头文件。 |

**整理者示例。** 如果 `event.h` 自身用了其他头文件声明的类型，应先包含它所依赖的头文件。再用独有的保护宏包住声明。预处理器遇到同一文件第二次时，宏已经定义，会跳过这部分。[GCC 预处理器文档：头文件包含保护](https://gcc.gnu.org/onlinedocs/cpp/Once-Only-Headers.html)

```c
#ifndef GAME_EVENT_H
#define GAME_EVENT_H

void setup_events(void);

#endif
```

课堂中，讲师展开 Visual Studio 的 Solution Explorer，Source Files 下只有 `run_app.c`。约 03:12 打开的微软 `errno.h` 中可见 `#pragma once`、`#ifndef _INC_ERRNO`、包含 `corecrt.h` 的指令、函数声明和错误码宏。屏幕最后是四条用途注释和直接返回的 `main`。本节没有新建头文件、编译多文件程序或比较构建用时。
