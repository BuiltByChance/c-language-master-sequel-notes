# P102 命令行参数

终端在启动程序时就能把文字交给它。C 程序若要读取这些文字，用 `int main(int argc, char *argv[])`。在课堂的 Windows 环境中，`argc` 把程序名也算作一项，`argv[0]` 是启动时使用的程序名或路径。用户附加的第一项在 `argv[1]`，最后一项在 `argv[argc - 1]`；`argv[argc]` 是空指针。程序无需读取命令行时，`int main(void)` 仍然适用。[Microsoft Learn 的 main 参数说明](https://learn.microsoft.com/zh-cn/cpp/c-language/arguments-to-main?view=msvc-170)

**从 Visual Studio 到命令提示符**

1. 在 `main` 中打印 `argv[0]`，再打印用户参数数目 `argc - 1`。用 `for (int i = 0; i < argc; ++i)` 逐项输出下标和 `argv[i]`。约 03:31，直接从 IDE 运行时，控制台报告用户参数为 0，并在第 0 项显示这个 Debug 可执行文件的完整路径。
2. 在工具栏选 **Release** 和 **x64**，通过 **Build → Rebuild Solution** 生成可执行文件。按 `Ctrl+Alt+L` 打开解决方案资源管理器，右击项目选 **Open Folder in File Explorer**。在课堂工程的 `x64\Release` 中找到 `teaching.exe`。双击程序的窗口很快关闭；讲师用 Windows 的 `pause` 临时等候按键。从已有命令提示符运行，输出可直接留在窗口里查看。
3. 在 `cmd` 切换到包含程序的目录，运行 `teaching.exe -h off 0`。讲师的桌面由 OneDrive 管理，最后将程序复制到命令提示符的当前目录运行。本次输出的 4 项依次是 `teaching.exe`、`-h`、`off`、`0`，所以屏幕报告用户传了 **3** 个参数。此时第 0 项只有文件名。

末项 `"0"` 仍是字符串；`-h` 在这段程序里也只是被打印的文字。要让它显示帮助，需先确认 `argc > 1`，再检查 `argv[1]` 的内容并调用相应操作。讲师把按参数执行功能留到下一节。若 Windows 上的一个参数含空格，用双引号括起整项，例如 `teaching.exe "two words"` 的用户参数数目为 1（整理者例）。[Microsoft Learn 的参数拆分规则](https://learn.microsoft.com/zh-cn/cpp/c-language/parsing-c-command-line-arguments?view=msvc-170)
