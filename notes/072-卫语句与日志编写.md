# P72 续上节：卫语句与日志编写

上一节的玩家列表按一次一人的方式增长。本节在 `updatePlayerList` 添加**卫语句**：先判断哪些请求应该立即结束，只有可以添加玩家时才申请内存。这样，控制台看到“请求无变化”和“扩容失败”时，可以区分是哪一步没有完成。

| 条件 | 课堂处理 | 数组及人数 |
| --- | --- | --- |
| `newSize < *currentSize` | 记错误日志并直接返回，阻止添加函数缩短列表。 | 已有玩家保留。 |
| `newSize == *currentSize` | 记提示日志并直接返回。 | 不调用 `realloc`。 |
| 目标更大，但正大小的 `realloc` 返回 `NULL` | 通过临时指针判定失败，记错误日志。 | 保留原指针和人数。 |
| 扩容成功 | 回写指针、在原人数对应的下标写入玩家，再更新人数，记录两条信息。 | 多一条已初始化的玩家记录。 |

课堂调用端每次传 `currentSize + 1`，因此每次只需写一个新槽。若向同一函数传入比旧人数大好几位的值，现有代码仍只填写一人，之后的打印会冒用未填写的位置。要支持提前预留空间，须把已用人数和容量分别存储。课堂另有一处错误日志沿用了“新大小小于当前值”的文字，放在分配失败分支会误指原因，应按实际失败操作报告。[微软 C 运行库：realloc](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/reference/realloc?view=msvc-170)

## 让日志指向具体事件

`logInfo` 和 `logError` 将级别、消息交给同一个 `logMessage`。添加成功后，第一条信息说明玩家已加入，第二条用 `snprintf(infoMessage, sizeof infoMessage, "Current player count: %d", *currentSize)` 记录人数。两种级别最终都由 `fprintf(stderr, ...)` 写往标准错误流。

时间戳用 `time(NULL)` 取得，微软 `ctime_s(timeStr, sizeof timeStr, &now)` 转换成本地时间字符串。课堂提供 26 个字符的缓冲区，成功时用 `timeStr[24] = '\0';` 去掉倒数第二个字符，即末尾换行，使时间、级别和消息留在同一行。转换失败时另行报告时间错误；复用此逻辑时还应先检查 `time` 是否返回 `(time_t)-1`。[微软 C 运行库：ctime_s](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/reference/ctime-s-ctime32-s-ctime64-s-wctime-s-wctime32-s-wctime64-s?view=msvc-170)

## 课堂验证

更新函数原先遗漏返回类型，遇到没有返回值的 `return;` 时出现 MSVC 的 C4033 警告。讲师给声明和定义都补上 `void`。现代 C 应显式声明返回类型，入口可写 `int main(void)`。

最后一次运行可见六条带时间和 `INFO` 的记录，人数依次为 1、2、3；随后列出 PlayerOne、PlayerTwo、PlayerThree，退出码为 0。本次没有触发缩容、相等或分配失败分支。保存到文件、使用其他日志库只在讨论中出现。片尾的主程序仍从打印直接返回，实际使用时应在返回前释放最终的 `players`。
