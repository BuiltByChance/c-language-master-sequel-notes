# P71 游戏服务器动态玩家列表管理：realloc 与多级指针的应用

一个新的 `Player` 已经有编号和名字，怎样把它加入调用者的动态数组？`realloc` 扩容后可能给出新的首地址，添加函数必须能把这个地址写回主程序。打印函数只读已有记录，接收数组首地址即可。这就是本例需要区分 `players` 与 `&players` 的原因。

## 一次加入一名玩家

课堂的 `Player` 含 `int id` 和 `char name[30]`。主程序以 `Player *players = NULL;`、`int currentSize = 0;` 表示空列表。每加入一人，就调用一次 `updatePlayerList(&players, &currentSize, currentSize + 1, newPlayer)`。

1. 第一个实参的类型是 `Player **`，函数通过它改写主程序的首地址。第二个是 `int *`，用于更新主程序的玩家数量。第三个是新的总元素数，第四个是要加入的整条记录。
2. 函数把 `realloc(*players, newSize * sizeof(Player))` 的结果先存到临时指针。首次传给 `realloc` 的旧首地址为 `NULL`，正大小请求会分配第一块空间。后续成功扩容时原有玩家记录保留，调用者改用返回的地址，不再释放旧地址。
3. 成功后用 `*players = temp;` 回写地址，再执行 `(*players)[*currentSize] = newPlayer;`。原来有两人时下一个可用下标是 2。写好后才把 `*currentSize` 改为 3。若正大小申请失败，函数打印错误，原地址、原人数和已有记录仍有效。[微软 C 运行库：realloc](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/reference/realloc?view=msvc-170)

课堂函数一次只初始化一个新槽，所以要保持 `newSize == currentSize + 1`。若想一次预留多个空位，应另记“容量”和“已加入人数”，打印只遍历已写入的记录。使用外部数量时，还要在加一、再乘每项大小前确认结果可表示，避免实际分配空间小于预期。

## 怎样核对添加成功

约 18:42，程序已运行但控制台没有业务输出，因为主程序还没调用 `printPlayers`。加上打印时一度错误地传入二级指针，约 19:16 显示乱码。按函数的 `Player *` 参数改为 `printPlayers(players, currentSize)`，约 19:47 控制台按顺序列出三条记录，进程退出码为 0。

| ID | 名字 |
| --- | --- |
| 1 | PlayerOne |
| 2 | PlayerTwo |
| 3 | PlayerThree |

本次运行模拟三次加入，分配失败、匹配拒绝与断网只在口头讨论。讲师在片尾提醒释放数组，但最后可见的 `main` 从打印直接返回。复习时应在所有读取完成后调用 `free(players);`。课堂的更新函数定义还缺显式返回类型；若让调用者知道是否加入成功，可声明返回 `int`，在成功和失败路径分别返回状态。
