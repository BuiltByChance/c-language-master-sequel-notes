# P63 传统数组的问题：输入长度未知时怎样选容量

讲师先写 `int arr[10];`，随后以 `char buffer[1000];` 讨论键盘输入。方括号中的数表示**容量**。数组创建后，即便用户只输入两个字节，它依然是容量为 1000 的字符数组。如果要保存以 `\0` 结尾的 C 字符串，最多装 999 个数据字节；多字节编码中的一个汉字可能占用多个字节。

| 需求 | 如何选择 |
| --- | --- |
| 已知一个合理的上限，超过上限允许拒绝 | 可选固定数组，给字符串终止符留一格。在保存前检查所需容量，对超限输入明确报错。 |
| 输入很长，但只需逐段读取、统计或写出 | 可分块复用同一固定数组，处理完一块再读取下一块。无需让一个数组容纳整个输入。 |
| 只有运行时才知道长度，而且后续必须保留整份数据 | 可按已知长度申请空间，或边读取边扩容。分别记录已用字节数和分配容量，先确认申请成功再写入，使用完释放。 |

后两种做法是整理者对选型的补充。课堂所说的“浪费”，是已预留的空间远多于实际数据；写出容量范围才涉及越界。它们也有别于动态分配后遗失释放机会的内存泄漏。带长度参数的输入函数可以限制一次写入，但不会替数组扩大容量。

“编译前就定大小”适用于画面中用常量声明的数组；有的 C 实现支持创建时才计算长度的变长数组，但同一个数组对象创建后仍不能增长。课上列出的动态分配用途是处理可变大小的数据、构造数据结构和调配资源。讲师在编辑器中写下声明和注释，没有输入数据、调用分配函数或测量内存占用。[WG14 C11 草案 §6.7.6.2](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=147) · [微软的 malloc 说明](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/reference/malloc?view=msvc-170)
