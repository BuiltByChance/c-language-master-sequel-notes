# P44 用 r+ 模式修改日志记录

讲师用自建的模拟日志 `frank.log` 演示如何更新某一条记录。任务是找到含有 `Memory usage exceeds 80% of available memory.` 的第一行，把整条告警改为内存使用恢复正常的通知。选择 `"r+"` 是因为文件已经存在，需要先读再写，而且不能在打开时清空。这个模式允许在当前位置覆盖数据，后面的字节不会自动前移或后移。[Microsoft Learn 的文件打开模式](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/reference/fopen-s-wfopen-s?view=msvc-170)

## 课堂代码如何工作

1. 自定义函数 `update_log_record_s(filename, search_str, replace_str)` 返回 `errno_t`。它检查三个指针，遇到空指针返回 `EINVAL`。空指针检查不能排除空字符串，如果搜索条件必须有内容，还要检查 `search_str[0]`。
2. 用 `fopen_s` 以 `"r+"` 打开已有文件，再用 `fgets` 循环读取。每次用 `strstr(buffer, search_str)` 查找子串，首次命中即停止。函数用搜索词选出记录，替换文本包含整行的新时间戳、级别和消息。
3. 代码试图以 `ftell(file_ptr) - (long)strlen(buffer)` 推算刚读过的行首，再用 `fseek(file_ptr, position, SEEK_SET)` 返回那里。随后把旧行改成空格和换行写回，再次定位并用 `fputs` 写入替换串。长度检查只比较两个参数与数组容量，无法保证新记录放得进文件中的旧位置，也无法保证一次 `fgets` 读到了整条记录。
4. `main` 收到 0 时输出 `Record updated successfully.`。未匹配分支返回 `ENOENT`，经 `strerror_s` 转成“没有这个文件或目录”的文字。此处即使文件存在，仅搜索失败也会产生这条消息，最好给“文件打不开”和“记录不存在”分别提供诊断。

## 运行结果为何和提示不同

- **英文日志。** 新的 `[INFO] Memory usage is back to normal levels.` 确实写入了。29:40 左右重开文件，第四行开头多出一个 `M`，原本下一行的一部分也接到了它后面。手工整理、再运行后，30:19 画面中第四行仍以两个左方括号 `[[` 开头。程序报告成功时没有核验周围记录是否完整。
- **数字日志。** `zhangsan.log` 原有三行 `123`、`456`、`789`。想把首行改成 `666`，看到的却是 `1666`、`56`、`789`。最后把另加的末行 `888` 改为 `666`，33:57 重开确实看到了末行变化，前面两行的异常仍在。
- **中文搜索。** 中途构建曾因旧进程占用 `teaching.exe` 报 LNK1104。解决这个构建问题后，查找“天气”仍进入错误分支。讲师猜测与编码有关，没有比对输入文件与程序里搜索串的实际字节。文件名是拼音 `zhangsan.log`，这次运行未确定中文匹配失败的根因。

## 同类任务怎样选方法

**定长记录**可以原位覆盖。读每条记录**之前**用 `ftell` 记下位置，位置有效且命中后将该值原样传给 `fseek(fp, pos, SEEK_SET)`，检查定位成功再写。确认覆盖区间和新数据的编码字节数相同，保留行结束符。Windows 文本模式会转换 CRLF，`strlen` 计算的是已读入内存的字节数；文件位置不能靠它可靠地倒算。讲师提到额外减 1，画面注明未经测试。[Microsoft Learn 的 fseek 文本流限制](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/reference/fseek-fseeki64?view=msvc-170)

**变长日志**可读原文件、写新的临时文件。整理者建议按完整记录处理，首条匹配记录写新内容，其余原样复制。确认读完无错、写入和关闭成功，再核对匹配行及其前后一行，最后才替换原文件。中文搜索还要保证文件和搜索串使用相同编码，才能按字节查找。
