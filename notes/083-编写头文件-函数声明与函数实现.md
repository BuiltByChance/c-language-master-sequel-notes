# P83 编写头文件：函数声明与函数实现

把加法和乘法做成一个小模块，需要回答三个问题：其他文件怎样知道函数签名，函数体放在哪里，构建时怎样把调用与实现连起来。课堂在 Visual Studio 的同一项目中完成了这三步。

1. **建立头文件。** 在菜单 `View → Solution Explorer` 或按 `Ctrl+Alt+L` 打开解决方案资源管理器。在 `Header Files` 上右击，选择 `Add → New Item`。课堂对话框默认显示 `FileName.cpp`，需把完整名称改为 `math_operations.h`。在其中声明 `int add(int a, int b);` 和 `int multiply(int a, int b);`。末尾的分号表示只有声明。
2. **建立实现文件。** 在 `Source Files` 下添加 `math_operations.c`，扩展名选择 `.c`。文件开头写 `#include "math_operations.h"`，以相同的返回类型和参数定义两个函数，函数体分别返回 `a + b`、`a * b`。实现和头文件取相同基本名便于查找；真正使调用可用的是该源文件参与编译，并且链接时能找到对应的函数定义。
3. **让调用者看到声明。** 在已有的 `run_app.c` 里同样包含 `"math_operations.h"`。课堂的 `main` 写下 `int resut = add(5, 6);`，随后返回成功。双引号适合查找本项目头文件；在 MSVC 中双引号和尖括号的搜索顺序不同，尖括号也能包含配置在搜索路径中的第三方头文件。[微软 C/C++ 文档：#include 的查找顺序](https://learn.microsoft.com/zh-cn/cpp/preprocessor/hash-include-directive-c-cpp?view=msvc-170)

**怎样写包含保护。** 课堂早期画面有 `#ifndef MATH_OPERATIONS_H` 和 `#endif`，中间缺少将宏设为已定义的那一行。这样第二次包含时条件依旧成立。下面是整理者补全后的写法，同一个翻译单元中通过该保护后，第二次遇到此头文件才会跳过声明部分。[GCC 预处理器文档：包含保护](https://gcc.gnu.org/onlinedocs/cpp/Once-Only-Headers.html)

```c
#ifndef MATH_OPERATIONS_H
#define MATH_OPERATIONS_H

int add(int a, int b);
int multiply(int a, int b);

#endif
```

片尾讲师改用 MSVC 支持的 `#pragma once`，放在头文件顶部并保留两条声明。这也是针对每个翻译单元的重复包含；是否在下一次构建时跳过某个源文件，另由构建系统的依赖判断决定。[微软 C/C++ 文档：once 杂注](https://learn.microsoft.com/zh-cn/cpp/preprocessor/once?view=msvc-170)

讲师通过 Ctrl 加单击从 `add` 的调用跳到实现。约 07:53，构建输出列出两个 `.c` 文件，一个项目成功、零个失败，调试控制台显示进程退出码为 0。代码没有打印 `resut`；按加法实现可推得 11，但屏幕没有显示这个数，乘法也没有被调用。整理者验证方法：在 `add` 调用后的下一行设断点，调试时查看局部变量 `resut` 是否为 11。
