# P45 用临时文件替换一条日志

上一节用 `"r+"` 原位覆盖日志，写出的新行影响了下一行。这节保留同一个接口 `update_log_record_s(filename, search_str, replace_str)`，把输出改写到另一个文件。新行有多长，就向新文件写多长；下一条记录接着写，边界无需用旧文件的位置倒推。课堂还展示了读者保留的上一版源码与另一份实现，讲师现场运行的是自己的修订版。[上一节源码](https://github.com/junq0420/demo_codebase/blob/main/frank_c_master/stream/frank_216_section_video_src.c) · [读者的实现](https://github.com/junq0420/demo_codebase/blob/main/frank_c_master/stream/read_and_write_file.c)

## 一次更新的流程

1. 检查三个参数是否为 `NULL`；有空指针就返回 `EINVAL`。用 `tmpnam_s` 将候选临时文件名写入长度为 `L_tmpnam_s` 的字符数组。这一步只生成名字，尚未创建文件；生成名字和打开文件之间，名字可能被别的程序使用。[Microsoft Learn 的 tmpnam_s 文档](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/reference/tmpnam-s-wtmpnam-s?view=msvc-170)
2. 以 `"r"` 打开原日志，再以 `"w"` 打开临时输出。若后一步失败，应关闭前一步打开的输入流。
3. 初始令 `found = 0`。用 `fgets` 读输入，遇到 `found == 0` 且 `strstr(buffer, search_str) != NULL` 时，向临时文件写整条替换串和一个换行，设 `found = 1`。其余内容通过 `fputs` 原样写入。因此即使后面也有相同搜索词，程序只替换第一条。
4. 关闭两个流。如果没有匹配，删除临时文件、保留原日志；课堂返回 `ENOENT` 表达“记录未找到”。若有匹配，课堂先 `remove(filename)` 删除旧文件，再 `rename(temp_filename, filename)` 将临时文件改为原名。微软 CRT 的 `rename` 要求目标名尚不存在。[Microsoft Learn 的 rename 文档](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/reference/rename-wrename?view=msvc-170)

## 现场验证

运行前，`frank.log` 的第四行只有 `Memory usage exceeds`。程序结束后，讲师在 VS Code 中查看同一文件，第四行已改成以下较长记录。下一行仍以完整时间戳开头，内容为 `Data synchronization with server started.`。

```text
[2023-02-14T12:36:15Z] [WARN] High memory usage detected. Threshold: 80%.
```

## 用于其他文件时的条件

- 课堂的 `BUFFER_SIZE` 是 2048，一个 `fgets` 最多读 2047 个数据字节。若一条记录可能更长，先拼出完整行再匹配，否则跨两段的搜索词可能漏掉，替换了首段后旧行的后半段也可能被继续复制。
- 整理者补充，发布新版本前应检查原流的 `ferror`、每次写入的返回值和输出流的关闭结果。课堂“先删再改名”分两步执行；若第二步失败，原名已消失。需要保留旧版本时，在目标目录独占创建临时文件，确认写入完整后，用平台提供的替换操作并保留备份。Windows 可使用 `ReplaceFileW`。本节只运行了正常替换，没有模拟写入或改名失败。[Microsoft Learn 的 ReplaceFileW 文档](https://learn.microsoft.com/zh-cn/windows/win32/api/winbase/nf-winbase-replacefilew)
