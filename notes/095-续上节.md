# P95 续上节：完成内存分配、重分配与释放包装函数

上节停在 `aligned_alloc` 的调用。00:14 的 E0020/C2065 实际诊断为 `max_align_t` 未定义，构建结果为 0 成功、1 失败；这个诊断本身没有检验 `aligned_alloc` 的链接结果。讲师查看了头文件和项目属性，把当前配置的 C 语言标准恢复为默认的 Legacy MSVC，使条件编译转入 `malloc(size)` 分支，再完成 `memory_manager.c` 中三个函数。

## 三个包装函数的实际行为

| 函数 | 正常与失败路径 |
| --- | --- |
| `safe_malloc(size)` | 用 `assert(size > 0)` 表达前置条件。申请失败时，先用 `fprintf(stderr, ...)` 报告请求字节数，再触发 `assert(ptr != NULL)`。启用断言的构建会在这里中止；关闭断言时才会执行到最后的 `return ptr` 并返回空指针。头文件所说“失败返回 NULL”因此要结合构建设置理解。 |
| `safe_remalloc(ptr, newSize)` | 自定义函数沿用屏幕拼写，内部调用标准 `realloc` 并返回其结果。正大小请求失败时尝试记一条 ERROR，旧块仍由调用者持有。调用者应先以临时指针接收，成功后才更新所有者。 |
| `safe_free(void **ptr)` | 指针变量的地址有效、其中保存着自己持有的有效分配块时，释放并把这个变量置为 `NULL`。参数本身为空，或持有者已经为空，则尝试记 WARNING。日志的实际可见性还取决于 logger 是否初始化以及级别阈值。 |

下面是整理者的调用示例，按课堂走通的编辑路径选择普通 `malloc` 分支。示例用 `void *` 保存所有者，`&block` 与 `safe_free` 的参数类型正好匹配。正大小扩容失败时仍然释放原块；成功时释放的是返回的新块。释放函数只能清掉传进去的这个变量；非空的旧别名仍不能安全使用。

```c
void *block = safe_malloc(32);
if (block == NULL)
    return EXIT_FAILURE;

void *larger = safe_remalloc(block, 64);
if (larger == NULL) {
    safe_free(&block);
    return EXIT_FAILURE;
}
block = larger;
safe_free(&block);
```

## 平台条件与演示结果

课堂用 `__STDC_VERSION__ >= 201112L` 在 C11 对齐分配和普通 `malloc` 之间选择。这个宏能识别语言标准模式，无法证明具体运行库提供 `aligned_alloc`。微软 UCRT 的确未实现该函数。普通分配可直接使用标准 `malloc/realloc/free`；需要微软显式对齐分配时，应使用配套的 `_aligned_malloc`、`_aligned_realloc`、`_aligned_free`。核实于 2026-11-24。[微软 C 语言符合性说明](https://learn.microsoft.com/zh-cn/cpp/overview/visual-cpp-language-conformance?view=msvc-170) · [微软对齐内存函数表](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/data-alignment?view=msvc-170)
