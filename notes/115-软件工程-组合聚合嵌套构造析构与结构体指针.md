# P115 软件工程：组合、聚合、嵌套、构造、析构与结构体指针

图书馆要能加书、按编号查找，还要在关闭时一次清理馆藏。课堂用了两层独立分配：图书馆持有一段连续的 `Book` 数组，每本书再持有一份单独复制的书名。先画清“谁拥有哪块存储”，就能决定在哪里复制、扩容和释放。

```c
typedef struct {
    int id;
    char *title;
    double price;
} Book;

typedef struct {
    Book *books;
    size_t count;
    size_t capacity;
} Library;
```

## 单本书如何创建和清理

`create_book(id, title, price)` 接收以零结尾的书名，为副本分配 `strlen(title)+1` 字节，复制时连同末尾的 `'\0'` 一起写入，再按值返回 `Book`。调用者能在函数返回后继续使用书名，因为副本位于独立的动态存储中。若再写 `Book b = a;`，则只复制了地址，两本书不能都把这同一块内存当成自己的来释放。

首次构建因该 MSVC 项目将 `strcpy` 的 C4996 诊断当成错误而停止。讲师把价格改用 `double`，并在包含头文件前定义 `_CRT_SECURE_NO_WARNINGS`，保留 `strcpy`。该宏只影响对应诊断，目标容量仍须由程序保证。09:42 控制台打印了编号 1 的 C++、价格 99，以及编号 2 的 Java、价格 1000。随后按源码调用 `free_book(&book1)` 和 `free_book(&book2)`，各自释放书名并置空；两个 `Book` 本体是 `main` 里的局部对象。[Microsoft Learn，CRT 安全功能](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/security-features-in-the-crt?view=msvc-170)

## 从建馆到销毁

1. **创建馆藏。** `create_library(2, &error)` 从零初始化的 `Library` 开始，请求能容纳两本书的数组，成功时 `count=0`、`capacity=2`。函数按值返回结构体，通过有效的 `ErrorCode *` 写出状态。零初始容量返回 `INVALID_PARAMS`，分配失败返回 `MEMORY_ERROR`。
2. **添加一本。** `add_book` 先检查馆指针、书名指针和价格，再遍历已有条目的 `id`。重复编号立即返回 `DUPLICATE_ID`，不增加书数。当 `count == capacity` 时，用临时指针接收 `realloc` 的结果，成功才将 `books` 和容量更新为新的地址与两倍容量。接着分配、复制书名，写入 `books[count]` 的各字段，最后才增加 `count`。若书名分配失败，即使数组刚刚扩过容，旧馆藏和书数仍然有效。整理者补充：计算翻倍容量和分配字节数前，还需检查上限。
3. **查找和打印。** `find_book` 只遍历前 `count` 项。编号命中则返回 `&books[i]`，未找到则置 `NOT_FOUND` 并返回 `NULL`。这个返回值借用馆藏数组的元素，不能单独释放；扩容成功或图书馆销毁后，旧指针不能继续使用。课堂写了查找函数但没有调用。实际展示列表的是 `print_library`，按已存书数逐本读出编号、书名和价格。[Microsoft Learn，realloc](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/reference/realloc?view=msvc-170)
4. **清理馆藏。** `free_library(&lib)` 先逐本释放前 `count` 项各自的书名，再释放 `books` 数组，最后将 `books` 置空，`count` 和 `capacity` 置零。尚未装书的空槽不用逐个清理。约 36:13 编辑器曾给出 C6001 代码分析警告，课堂在修改清理逻辑，没有演示运行时崩溃。

## 如何判断嵌套、组合和聚合

- **嵌套**看布局。若在 `Library` 中直接写 `Book books[100]`，100 个 `Book` 对象就内嵌在馆对象里，槽数固定。即使用这种布局，每本书单独申请的书名仍要显式释放。
- **组合**看持有和清理责任。本例由图书馆创建、管理并销毁书数组，书名也在添加时复制并在销毁时释放。讲师把单独分配的 `title` 称为“聚合”；沿实际的分配、复制、释放路径看，这份副本归馆藏所有。字符串位于结构体之外，并不足以判定它是借来的。
- **共享聚合**的具体语义取决于建模约定。可以对照一个借用设计（整理者补充）：若目录只记录外部已管理的书，外部所有者须保证书仍有效，目录销毁时只清理它自己的索引。实现里两个设计都可以写成指针，差别落在寿命和释放协议上。[OMG UML 2.5.1，§9.5.3 聚合种类](https://www.omg.org/spec/UML/2.5.1/PDF)

课中的“构造”和“析构”分别指显式调用的初始化函数和清理函数。局部结构体到达作用域末尾时，C 不会替它调用 `free_library`。漏掉清理会影响仍在运行的进程；讲师说关闭程序后还需重启才能回收，本例所用 Windows 会在进程终止时回收其私有内存。末尾只列出自引用、链式结构，未另写链表或树。[Microsoft Learn，进程终止时的资源回收](https://learn.microsoft.com/en-us/windows/win32/procthread/terminating-a-process)
