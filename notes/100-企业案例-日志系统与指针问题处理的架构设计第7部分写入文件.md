# P100 日志系统与指针处理（七）把应用日志写入文件

在 `application_logic.c` 中定义 `#define PATH "application.log"`，把 `app_init()` 中的 `logger_init(NULL)` 改为 `logger_init(PATH)`。原有调用点继续用 `log_message` 记录事件，输出目的地由初始化参数决定。讲师口头将此前的控制台日志称为 `stderr`；日志模块实际在参数为 `NULL` 时选 `stdout`，初始化失败的诊断才由 `fprintf(stderr, ...)` 输出。

1. 从 Visual Studio 运行程序。路径只有文件名，`application.log` 会出现在进程的工作目录。课堂中该目录恰好包含 `application_logic.c` 和工程文件。`logger_init` 用 `"a"` 打开日志，文件不存在时尝试创建，已存在时把新消息追加到末尾。[Microsoft Learn 的文件打开模式](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/reference/fopen-s-wfopen-s?view=msvc-170)
2. 打开生成的文件，按时间戳和消息核对本次运行。约 01:22，记事本显示六条记录，课堂时间均为 `2024-02-23 16:32:51`。其中 `[INFO] Data value set to 42.` 确认赋值，最后一条是 `[INFO] Cleaning up application...`。控制台没有这些业务消息，只看空控制台无法判断文件是否写好。

选择记录位置时，先想复查问题会需要什么证据。本例记下申请成功、实际整数值和清理时机，就能回溯一次运行执行到了哪一步。讲师特别提醒，登录等操作可以记录结果，密码本身应排除在日志之外。本节写入的是这个程序自己的日志文件。
