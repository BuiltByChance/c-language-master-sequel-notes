# P105 自定义泛型队列（二）记录内存用量与处理错误

假如队列用完后还有内存未释放，首先要知道哪些申请与释放经过了统计。课堂在 `MemoryManagement.c` 定义文件内共享的 `static size_t currentMemoryUsage`，再用三个包装函数管理这个计数。

| 操作 | 成功时的处理 | 失败或空值 |
| --- | --- | --- |
| `SafeMalloc(size)` | 调用 `malloc`，把请求字节数加入计数，返回分配指针。 | 分配失败写 `stderr` 并用 `exit(EXIT_FAILURE)` 结束程序。 |
| `SafeRealloc(ptr, newSize)` | 在 Windows 上先取得旧块大小，再用临时指针接收 `realloc` 结果；成功才更新计数、交回新指针。 | 课堂代码将分配失败作为进程终止条件。 |
| `SafeFree(void **ptr)` | 取得所指块的大小并扣除，释放块，把传入的指针变量写为 `NULL`。 | 先检查 `ptr` 和 `*ptr`。它能清空交给它的那个 `void *` 变量；其他别名不会随之改变。 |

Windows 分支实际调用的是 `<malloc.h>` 中的 `_msize`，口述和早期注释提到的 `_msize_s` 与代码不同。若按申请大小累计、再按分配器报告的块大小扣减，两种口径不一致时会产生错误的余额，甚至出现很大的无符号数。非 Windows 分支对旧块大小和释放扣减还留有 TODO。若要跨平台统计请求量，可在分配成功时自行记录每块的请求大小，扩容或释放时查同一份记录（整理者补充）。[Microsoft Learn 的 _msize](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/reference/msize?view=msvc-170)

`PrintMemoryUsage()` 以 `%zu` 显示当前字节数。若要保存快照，`MemoryManagement_DumpToFile(filename)` 用 `fopen_s` 的 `"w"` 模式打开报告文件，失败即报错并返回；成功则写入当前值并关闭文件。此模式每次覆盖旧报告。余额只反映接入包装函数的分配；直接调用 `malloc` 的队列节点不会自动计入。

**错误如何返回。** 第二个模块用 `ErrorCode` 表达无错误、内存分配失败、无效操作、越界四种状态。`SetErrorCode` 和 `GetErrorCode` 访问保存的当前错误，`GetErrorString` 把指定码映射为文字。`CheckNotNull(NULL)` 会设置并返回分配失败码；传非空指针只返回 `ERROR_NONE`，不会清掉先前保存的错误。`HandleError(code)` 先把文字写到 `stderr`，随后仅在 `code != ERROR_NONE` 时终止程序。这样即使传入“无错误”，也会打印一行诊断。

片尾讲师把误放在头文件中的函数体移至源文件，头文件保留声明。本节完成的是编码，没有运行队列、查看报告或测出内存泄漏。
