# P103 小案例：编写能求和的命令行程序

目标是在命令提示符输入 `teaching.exe -a 1 2`，让程序识别 `-a` 为加法选项，将后面的字符串转换为整数并打印和。这里的 `argv[0]` 是程序名，`argv[1]` 是选项，操作数从 `argv[2]` 开始。本次共四项，所以 `argc == 4`。

1. 在 `main(int argc, char *argv[])` 中先检查参数数目，再用 `strcmp(argv[1], "-a") == 0` 判断选项。课堂条件为 `argc >= 3`，匹配后调用 `processAdd(argc, argv)`。它允许一个或更多操作数；若接口要求恰好两个，就应检查 `argc == 4`。原代码遇到缺参或未知选项时直接以 0 结束，没有提示。
2. `processAdd` 将 `sum` 初始化为 0，用 `atoi` 把参数转换为整数并相加。课堂循环从下标 **0** 开始，把程序名和选项也送给 `atoi`。这次的 `"teaching.exe"` 和 `"-a"` 都转换为 0，所以仍得到 3。复写时从下标 **2** 开始，只处理操作数。[Microsoft Learn 的 atoi](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/reference/atoi-atoi-l-wtoi-wtoi-l?view=msvc-170)
3. 在 Visual Studio 构建 **Release / x64**，把 `x64\Release` 下的新 `teaching.exe` 放在命令提示符当前目录，运行上述命令。约 04:08，屏幕显示 `Sum: 3`。课堂只验证了这组有效输入。随后讲师用系统关机命令举例，只键入文字，没有执行。

**整理者补充。** 若要向使用者报告错误输入，改用 `strtol(arg, &end, 10)`。每项转换前设 `errno = 0`，转换后要求 `end != arg`、`*end == '\0'` 且 `errno != ERANGE`。这样既能接受合法的 `"0"`，也能拒绝无数字或末尾残留字母的参数。若累计和用 `int` 保存，还需检查每个数和每次相加的结果都在 `INT_MIN` 到 `INT_MAX` 内，再执行加法。[Microsoft Learn 的 strtol](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/reference/strtol-wcstol-strtol-l-wcstol-l?view=msvc-170)
