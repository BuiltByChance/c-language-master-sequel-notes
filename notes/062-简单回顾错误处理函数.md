# P62 简单回顾错误处理函数

想知道文件为什么打不开，先按打开函数的约定判断它是否失败。例如 `fopen` 遇错返回 `NULL`。如果该接口用 `errno` 报告原因，应在失败后立即读取它，或者先保存为 `int code = errno;` 再处理。成功调用后可能还留有旧值，`errno != 0` 本身不足以判定本次失败。若用 `fopen_s` 这类直接返回错误码的接口，可保存它自己的返回值。

| 想做什么 | 接口和头文件 | 如何使用 |
| --- | --- | --- |
| 程序根据原因选择下一步 | `<errno.h>` 的 `errno` 和符号常量 | 比较 `code == ENOENT`（找不到文件或路径成分）或 `code == EACCES`（权限不足）等，使用符号名可避免依赖某台机器的错误编号。 |
| 立即把当前错误告诉用户 | `<stdio.h>` 的 `perror` | 例如在 `fopen` 失败后立即调用 `perror("打开配置文件")`，前缀、当前 `errno` 的说明和换行会写入 `stderr`。参数是上下文文字。 |
| 取得已保存错误码的说明，供日志或界面使用 | `<string.h>` 的 `strerror`，或微软 CRT 的 `strerror_s` | `strerror(code)` 返回说明字符串；`strerror_s(msg, sizeof msg, code)` 将说明写入自己的 `char msg[256]`。后者成功返回 0，再用 `fprintf(stderr, "%s\n", msg)` 等函数输出。 |

讲师先在 `errno.h` 浏览错误常量，再在 `stdio.h`、`string.h` 查到函数声明。编辑器最后保留的 `perror()`、`strerror()` 都缺少必需参数，有红色诊断标记。本节没有构建或运行程序，文件打开失败的结果来自前面课程的回顾。下一章预告为动态内存管理。[微软的 perror 说明](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/reference/perror-wperror?view=msvc-170) · [微软的 strerror_s 说明](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/reference/strerror-s-strerror-s-wcserror-s-wcserror-s?view=msvc-170)
