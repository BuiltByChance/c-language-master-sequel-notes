# P99 日志系统与指针处理（六）用程序入口验证模块

在 `run_app.c` 包含 `"application_logic.h"`，用 `main` 串起三个阶段。先调用 `app_init()`，本例用 `logger_init(NULL)` 将日志指向标准输出，阈值设为 `LOG_DEBUG`。初始化成功才调用 `app_execute()`。执行阶段申请一个整数、写入 42、记录该值并释放内存。最后 `app_cleanup()` 记录清理消息并关闭日志。这样可在控制台对照程序走过的阶段及其顺序。

| 现场顺序 | 日志内容 | 可以确认的事实 |
| --- | --- | --- |
| 1 | INFO，Application initializing... | 初始化路径已打开日志 |
| 2–3 | DEBUG，开始执行、内存已分配并准备赋值 | 本次申请走到了成功分支 |
| 4 | INFO，Data value set to 42. | 程序读回并打印了写入的整数 |
| 5–6 | DEBUG，Finishing app_execute.；INFO，Cleaning up application... | 执行函数结束，进入清理函数 |

约 04:37，Visual Studio 的 Debug x64 构建成功，控制台显示以上六条消息，进程退出码为 0。片尾代码还写有 `Application exited successfully.`，实际输出中没有这句话。`main` 先调用了已关闭日志的 `app_cleanup()`，接着又调用 `logger_close()`，最后才尝试记成功消息。此时输出流已清空，日志函数直接返回。若要看到该消息，应在最后一次关闭日志之前写入，并由一个位置负责关闭。

讲师还给初始化失败和执行失败分支补上了 `EXIT_FAILURE`，课堂运行只覆盖了正常路径。如果初始化时就打不开日志，诊断要写到仍可用的通道，例如 `stderr`。原声将日志形容为“监听”变量，实际代码只在调用日志函数的位置记录当时的值。判空函数只检查是否为 `NULL`，本次测试也没有验证悬挂指针、分配失败或日志写入失败的处理。
