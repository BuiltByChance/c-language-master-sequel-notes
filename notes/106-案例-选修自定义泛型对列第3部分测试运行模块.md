# P106 自定义泛型队列（三，选修）用测试模块验证入队与出队

要让测试能够重复运行，可以把“安排输入、调用操作、判断结果”写成返回通过或失败的函数，再交给统一入口逐个调用。本节在 `TestAndValidation.h/.c` 中建立这套结构，实际注册了一个测试。

**这一个用例验证什么**

1. `Test_GenericQueue_Enqueue_Dequeue()` 创建队列，定义局部 `int testData = 42`，将 `&testData` 存入联合体的 `ptrValue`，带着标签 `TYPE_PTR` 入队。节点保存地址，整个用例期间该局部整数仍然有效。
2. 确认入队成功后，向 `Queue_Dequeue` 提供联合体和标签的输出位置。课堂依次核对出队返回值、标签是否仍为 `TYPE_PTR`、地址所指的整数是否仍为 42。整理时若希望同时验证“原来的指针确实被交回”，可以直接比较输出地址和 `&testData`，再读取这个已知有效的对象。
3. 正常路径销毁队列并返回 `TEST_PASSED`。创建成功后若在入队或出队检查处提前返回，原用例会跳过清理；复写时应让这些分支也销毁已获得的队列。

**如何让入口执行用例。** `TestCase` 将测试名称与同签名的函数指针配成一项，填入 `tests[]`。`main` 用 `sizeof tests / sizeof tests[0]` 算出项数，交给 `RuntestSuite(tests, testCount)`。运行器遍历数组、输出名称、调用 `tests[i].function()`，按 `TestResult` 增加通过数。头文件另外写了 `VERIFY` 宏，可在表达式失败时输出源文件名和行号；本次队列用例直接写判断分支。

约 18:13，源码中的 `print`、`frpintf` 拼写错误及测试函数名大小写不一致导致构建失败。修复后，约 19:39 控制台显示 `Test Suite Summary: 1/1 tests passed.`，进程退出码为 0。入口末尾固定返回 `EXIT_SUCCESS`，所以判断本次用例是否通过要看汇总，不能只看退出码。本次覆盖了**一个指针元素**的进出；多元素的先进先出顺序、内存用量统计和其他类型都没有运行测试。
