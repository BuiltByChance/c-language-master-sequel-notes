# P101 环境变量的读写

Windows 的 `PATH` 是一项环境变量，值中用分号分隔多个搜索目录。要判断程序能否看到某个工具目录，应读取**运行该程序的进程**所见的 `PATH`，再按分号拆开核对完整目录项。讲师在开始菜单搜索 `env`，展示了“编辑系统环境变量”和“编辑帐户的环境变量”入口。

**读取。** 标准 C 的 `getenv("PATH")` 在找不到变量时返回空指针。约 01:25，课堂 MSVC 工程将它的 C4996 弃用诊断当成错误，构建失败。随后在包含 `<stdlib.h>` 的源文件里改用 `getenv_s`。约 02:43，控制台打印了这台机器的 PATH，进程退出码为 0。

```c
/* 整理者写法：分开记录数组容量和所需长度。 */
char buffer[512];
size_t required = 0;
errno_t err = getenv_s(&required, buffer, sizeof buffer, "PATH");
if (err == 0 && required > 0) {
    printf("PATH: %s\n", buffer);
}
```

`required` 包含结尾零字符所占空间，等于 0 表示没找到变量。课堂的 512 字节只对这次输入够用；返回 `ERANGE` 时可按给出的所需长度扩大缓冲区后重读。若预先不知道容量，也可先用 `getenv_s(&required, NULL, 0, "PATH")` 查询，确认变量存在后再分配。[Microsoft Learn 的 getenv_s](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/reference/getenv-s-wgetenv-s?view=msvc-170)

**写入。** 讲师在编辑器写出 `_putenv_s("MY_VAR", "some_value")`，以返回 0 判断成功，随后把变量名改成 PATH 举例，没有运行写入或重新读取验证。这个函数会替换当前进程环境中该变量的整个值；若要保留已有 PATH 条目，须自行保留旧值并合并。讲师以安装器永久“加入 PATH”作类比，这个 API 的作用范围限于当前进程及其后续可继承该环境的子进程。[Microsoft Learn 的 _putenv_s](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/reference/putenv-s-wputenv-s?view=msvc-170)
