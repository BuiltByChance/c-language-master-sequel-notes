# P57 数学函数的错误处理：EDOM、ERANGE 和 HUGE_VAL

`sqrt(number)` 计算实数平方根。输入负数时，问题出在参数超出定义域。计算本身有意义、结果却超出返回类型的表示范围时，则属于范围错误。以库通过 `errno` 报错的环境为例，应在调用前设置 `errno = 0`，调用后立即检查它，避免把先前操作留下的错误算到本次调用头上。[微软的 sqrt 说明](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/reference/sqrt-sqrtf-sqrtl?view=msvc-170) · [C11 委员会草案 §7.12.1](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=249)

| 名称 | 在哪里检查 | 怎么判断 |
| --- | --- | --- |
| `EDOM` | `<errno.h>` 中的错误码，与 `errno` 比较 | 对 `sqrt` 而言，负实数超出定义域。 |
| `ERANGE` | `<errno.h>` 中的错误码，与 `errno` 比较 | 根据所调用函数的文档判断结果是否溢出或下溢。 |
| `HUGE_VAL` | `<math.h>` 中的 `double` 型宏，涉及函数返回值 | 某些函数在溢出时返回 `HUGE_VAL` 或 `-HUGE_VAL`。课堂写的 `errno == HUGE_VAL` 把浮点返回值与整数错误码混在了一起，这一行应去掉。 |

在课堂程序中，`scanf("%lf", &number)` 之后才清零 `errno` 并调用 `sqrt`。输入 `-16`，控制台显示“错误：输入值为负数，无法计算其平方根！”，进程退出码为 0，这是 `main` 最后返回的值。讲师随后输入两个很大的正数，都显示了平方根，最后停止尝试，没有触发范围错误。有限正 `double` 的平方根仍在该类型的数值范围内，增大这类输入不会让开方结果上溢。

自己处理交互输入时，先确认 `scanf("%lf", &number) == 1`，再决定能否计算。讲师在头文件之前定义了 `_CRT_SECURE_NO_WARNINGS`，用来关闭微软 CRT 针对这类函数的弃用诊断。它不会检查本次是否成功读到数字。跨实现复用 `errno` 的判断时，还应确认该数学库的 `math_errhandling` 启用了 `MATH_ERRNO`。[微软的 C4996 说明](https://learn.microsoft.com/zh-cn/cpp/error-messages/compiler-warnings/compiler-warning-level-3-c4996?view=msvc-170) · [微软的 HUGE_VAL 说明](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/huge-val-huge?view=msvc-170)
