# P92 用断言调试：最大值、图像尺寸与折扣

当某次调用没有产生预期输出，先找出函数依赖的输入条件，以及计算完后结果应满足的条件。把前者放在使用参数之前，把后者放在返回结果之前。启用断言的构建会指出第一个失败的表达式和代码行，再回到调用处追查参数来源。

## 整数数组的最大值

函数用第一个数组元素初始化最大值，随后逐个比较；遇到更大的数才更新。这样即使全是负数，也能以真实元素作为候选。课堂数组 `{3, 1, 4, 5, 6, 1, 4, 6, 8}` 的最大值为 8。以 `sizeof numbers / sizeof numbers[0]` 计算元素个数的前提是当前位置仍能看到完整数组。

课堂第二次调用给了空指针和零长度，原函数却假定存在首元素，未得到第二个最大值。改在读取首元素**之前**加 `assert(arr != NULL && length > 0)` 后，调试输出明确指向这个入口条件。若数组来自外部输入，实际接口还须先用普通分支拒绝空输入；即使地址非空，调用者也必须保证有至少 `length` 个可读元素。

## 图像尺寸

`processImage(width, height)` 只打印尺寸。课堂输入 `1024, 768` 会输出 `Processing an image of size 1024x768 pixels.`。原先单靠 `if (width > 50 && height > 50)` 才打印，传入 `50, 50` 时安静地跳过，调用者只会发现少一行。讲师随后为宽、高分别添加断言，两者都须严格大于 50、严格小于 10000。约 09:34，第一组照常打印，第二组停在宽度条件；高度断言排在后面，这次没执行到。课堂没有读取或处理真实图像。

## 折扣率

`calc(quantity)` 的课堂规则是 1～9 件无优惠，10～19 件减 10%，20～49 件减 20%，50 件及以上减 50%。折扣率是从价格中减去的比例，打印百分数时乘以 100。

- **入口条件**为 `quantity > 0`。没有断言时，屏幕显示 25 件优惠 20.00%，另一次模拟输入实际为 **−5** 件，竟也返回了 0.00%。字幕或口述中的“五”缺少负号，负号在源码和输出中均可见。加入断言后，负数输入在入口第 11 行触发诊断。
- **出口条件**为 `discount >= 0.0 && discount <= 0.5`，包含无优惠的零。它能发现折扣率算出负值或超过 50% 的错误，但不能发现把 25 件算成 10% 这类仍在范围内的错算，后者需要按档位核对。课堂写了出口断言，未故意制造越界折扣来触发它。

断言诊断的是程序内部假设。在包含 `<assert.h>` 时定义了 `NDEBUG`，表达式就不再求值。发布版本仍需处理的无效数量、尺寸或读入失败，应另写普通检查。[Microsoft Learn 的 assert 文档](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/reference/assert-macro-assert-wassert?view=msvc-170)
