# P87 指针的作用域和生命周期

看到 `*ptr` 时要分两步判断。**作用域**决定这行代码能否用名称 `ptr` 找到那个指针变量。**生命周期**决定这一时刻还有哪些对象存在。即使指针变量本身仍然存在，也要确认它指向的对象仍然有效，才能解引用。[C11 草案 §6.2.1、§6.2.4](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=54)

| 课中对象 | 从哪里访问、何时有效 |
| --- | --- |
| `int local = 5;` 和 `int *local_ptr = &local;` | 两者都定义在 `function` 的块内。函数内能通过 `*local_ptr` 读出 5。函数返回后两个对象的生命周期一同结束。即使原来的地址日后被复用，也不能再通过该地址读取原来的 `local`。 |
| 文件作用域的 `int *global_ptr;` | 指针变量在程序执行期间存在。在本文件的声明之后，`function` 和 `main` 都能用这个名称。 |
| `malloc(sizeof(int))` 成功分配的整数 | `function` 将地址存入 `global_ptr`，写入 10。函数返回后，分配的对象仍然有效，直到 `main` 调用 `free(global_ptr)`。释放后不要再解引用，可将持有者置为 `NULL`。 |

讲师原先说只展示代码。实际在约 07:24 构建并运行，控制台先显示 `Inside function: local_ptr points to 5`，再显示 `Outside function: global_ptr points to 10`，退出码为 0。第二行读到的是另行分配的整数；本次没有尝试在函数外读取已经结束生命周期的局部变量。

课堂最初对分配结果直接写 10，Visual Studio 提示可能解引用空指针。后来只在写入前加了 `if (global_ptr != NULL)`，`main` 里的读取仍然没有检查。整理者建议让分配函数返回成功或失败，调用者只在成功时打印和释放；在课堂现有结构中，也可以在 `function()` 返回后先判断 `global_ptr`，为空就返回失败。课程只运行了成功路径。
