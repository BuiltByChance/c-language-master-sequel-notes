# P113 结构体指针成员，再探动态内存、堆内存和栈内存

课堂在编辑器里定义了 `Book`，有 `int id`、`char *title` 和 `float price` 三个成员。`title` 在书对象中占一个指针的空间。创建这个结构体时，书名字符的存储要另外安排；复制结构体也只会把这个地址复制一份。课中展示了类型声明，实际运行的是后面的整数数组。

| 书名如何保存 | 何时适合 | 需要管理什么 |
| --- | --- | --- |
| 成员 `char title[50]` | 已知最长书名能放入 49 个数据字节 | 末尾留一格给 `'\0'`。每本书都自带 50 个字符槽，包含在 `sizeof(Book)` 中，书对象销毁时一起结束。 |
| 成员 `char *title` 指向自己分配的缓冲区 | 书名长度在运行时确定，希望按实际字节数储存 | 有一个有效的源字符串后，分配 `strlen(source)+1` 字节，判空再复制；不再使用时由拥有它的一方释放一次。 |
| 成员 `const char *title` 借用已有字符串（整理者补充） | 字符串在整段使用期间有效，而且使用者只需读取 | 无需为借来的字面量申请或释放存储；若借用来自其他对象的地址，确保那个对象活得足够久。 |

固定长度和静态存储期是两个问题。函数里的普通局部数组可以在进入块时创建、离开块时结束；全局对象和以 `static` 声明的局部对象则有静态存储期。动态分配块从分配成功持续到释放，和保存它首地址的局部指针有各自的生命周期。讲师用栈区、堆区、代码区和静态区说明常见实现。分析一段 C 程序时，可以直接问“现在谁还持有它，到哪一步可释放”。进程内失去最后一个可用地址会造成泄漏；讲师提到重启，并非解决泄漏的必要条件。[WG14 C11 草案 §6.2.4，对象的存储期](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=56)

## 由输入决定整数数组长度

1. `main` 读取整数 `n`，再向 `malloc` 请求 `n` 个 `int` 的空间。课堂检查了返回指针是否为 `NULL`，失败会向标准错误输出提示并返回 1。整理者补充：还要先确认输入转换成功、`n > 0`，且元素个数不超过 `SIZE_MAX / sizeof(int)`，再计算字节数。
2. 成功后，局部指针 `arr` 保存第一项的地址。依次执行 `arr[i] = i+1`，赋值后才逐项打印。22:00 输入 5 时，控制台出现 `1 2 3 4 5`。22:04 输入 10，则打印至 10。这些值来自循环，`malloc` 本身不会填入序号。
3. 讲师另加一个循环打印各项地址。24:44 再次输入 5，五个地址的末三位依次为十六进制的 `470`、`474`、`478`、`47C`、`480`。相邻地址相差 4 字节，对应该环境的 `sizeof(int)`。用 `printf("%p", (void *)&arr[i])` 可按 `%p` 要求传入地址。`arr` 的值指向首元素，`&arr` 则是局部指针自身的地址。
4. 所有读写完成后 `free(arr); arr = NULL;`。这一赋值清空当前变量；其他曾指向同一块的指针，需要同时停止使用。课堂运行的是正数输入，未触发分配失败，也未测内存泄漏。[Microsoft Learn，malloc](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/reference/malloc?view=msvc-170) · [Microsoft Learn，free](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/reference/free?view=msvc-170)
