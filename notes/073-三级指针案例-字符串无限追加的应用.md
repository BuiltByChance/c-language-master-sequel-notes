# P73 三级指针案例：字符串无限追加的应用

课堂依次添加 `"Hello"`、`"World"`、`"!"`。内存里始终是三条独立的 C 字符串，各有自己的结束符。控制台看起来像一个 `HelloWorld!`，是因为打印函数依次输出三项，中间没有分隔符。课名中的“无限追加”指运行时可以继续申请空间，实际数量受可表示的长度与可用内存限制。

## 什么时候需要第三层指针

每条字符串由一个 `char *` 指向。主程序的 `char **strArray = NULL;` 保存整张指针表的首地址，`int size = 0;` 记录当前字符串条数。添加函数可能换掉表的首地址，所以调用 `addString(&strArray, &size, "Hello")` 时，第一个形参是 `char ***array`。打印只遍历现有字符串，直接传 `printStrings(strArray, size)`。

| 在添加函数中 | 对应的对象 |
| --- | --- |
| `array` | 主程序中 `strArray` 变量的地址。 |
| `*array` | 指针表的首地址，成功扩容后要写回这里。 |
| `(*array)[i]` | 表内第 `i` 个槽，保存一条字符串的首地址。 |

## 追加与释放的顺序

1. 先按 `(*size + 1) * sizeof(char *)` 字节扩展指针表。课堂用临时变量接收 `realloc` 的结果。对正大小的申请，失败时原表仍有效，可以报告错误并返回；成功时才将新表地址写回 `*array`。[微软 C 运行库：realloc](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/reference/realloc?view=msvc-170)
2. 另行申请 `strlen(str) + 1` 字节保存新字符串，让新槽指向它。多出的一个字节留给 `'\0'`。若此次申请失败，已有字符串仍在，条数保持原值。成功后用 `strcpy_s` 复制。课堂直接增加条数；复用时应确认复制成功才增加，复制失败则释放刚申请的字符串空间。这样 `[0, size)` 的每个槽都指向可读的完整字符串。[微软 C 运行库：strcpy_s](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/reference/strcpy-s-wcscpy-s-mbscpy-s?view=msvc-170)
3. 用完后按 `0 <= i < size` 逐条调用 `free(strArray[i])`，最后 `free(strArray)`。外层表只保存地址，提前释放它会失去逐条回收所需的入口。

第一次构建同时报出 `strcpy` 的 C4996 和 `printStrings` 的声明问题。把复制改为 `strcpy_s` 后，仍因调用前没有打印函数的声明而构建失败；补上与定义一致的 `void printStrings(char **array, int size);` 后运行成功。约 08:41 的最终控制台可见 `HelloWorld!`。课堂未制造分配失败，也没有测量可添加条数的上限。
