# P81 游戏架构事件设计：事件类型、处理函数、注册与分发

游戏收到“攻击”或“移动”时，要选择不同动作。本例把**事件类型**用作查表的下标，把**玩家姓名**作为数据传给选中的处理函数。主程序手动发出两次事件，用控制台文字代替游戏动作。

## 从类型到处理函数

1. 用枚举 `GameEventType` 定义 `PLAYER_ATTACK` 和 `PLAYER_MOVE`，依次取 0、1。末项 `EVENT_COUNT` 等于 2，表示事件种类数，用作数组长度。讲师口头提到“发生了多少次”，但代码没有递增计数；这项也不能作为事件下标。
2. 统一签名 `typedef void (*EventHandler)(const char *playerName);`。每个处理函数都接收姓名并返回 `void`。课堂用字符串 `"Hero"` 作演示，改用玩家 ID 或整个玩家结构体只是后续设想。
3. 定义文件作用域的函数指针数组 `EventHandler eventHandlers[EVENT_COUNT];`。程序启动时两个槽都为空。注册函数把传入的处理函数指针放进对应槽，此时并不执行动作。再次注册相同类型会替换该槽原来的处理函数。
4. 分发函数查对应槽；已注册才用玩家姓名调用它。这里的处理函数只打印消息，并未计算伤害或更新坐标。

课堂的调用顺序如下。攻击函数名在源码里确实将结尾的 `k` 写了两次，声明、注册与定义使用相同拼写。

```c
registerEventHandler(PLAYER_ATTACK, handlePlayerAttackk);
registerEventHandler(PLAYER_MOVE,   handlePlayerMove);

dispatchEvent(PLAYER_ATTACK, "Hero");
dispatchEvent(PLAYER_MOVE,   "Hero");
```

约 19:50，控制台依次输出 `Hero attacks!`、`Hero moves!`，进程退出码为 0。两条消息携带同一个名字而动作不同，验证了系统按事件类型分发。没有监听键鼠、建立事件队列或测试“防御”事件。

## 修正下标检查

片尾讲师针对编辑器警告，在**注册**时先检查 `eventType >= 0 && eventType < EVENT_COUNT`，非法时向 `stderr` 报告。编辑器随后显示没有诊断提示，未用非法事件再次运行。最终屏幕上的**分发**函数仍直接查表再判断该槽是否为空；判空解决的是“合法事件有没有注册”，无法代替下标检查。

整理者补充的分发顺序如下。先排除范围外的编号，才读取对应函数指针。[C11 工作草案 §6.5.2.1、§6.5.2.2](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=98)

```c
void dispatchEvent(GameEventType eventType, const char *playerName) {
    if (eventType < 0 || eventType >= EVENT_COUNT) {
        fprintf(stderr, "Invalid event type\n");
        return;
    }
    EventHandler handler = eventHandlers[eventType];
    if (handler != NULL) {
        handler(playerName);
    }
}
```
