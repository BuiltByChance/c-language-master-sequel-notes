# P14 选修（难、非入门）——VS 编译器捕获字符串异常

在 Microsoft C 运行库（CRT）里，检查 `strcpy_s` 的返回值有一个前提：调用得先返回。参数无效时，运行库会调用无效参数处理函数。默认处理函数会终止进程，写在 `strcpy_s` 后面的 `if (err != 0)` 就没有机会执行。课中所说的“捕获异常”指的是注册这个回调。[Microsoft Learn：参数验证](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/parameter-validation?view=msvc-170)

## 同一次复制，为何能看到不同结果

源数组保存 `"hello"`，连同末尾的 `\0` 需要 6 个 `char`。讲师本节把目标实际声明成 `char dest[2]`，传入的 `sizeof(dest)` 如实报告了容量 2。验证失败的原因正是目标装不下。讲师在 Visual Studio 顶部工具栏切换 `Debug` 和 `Release`，目标平台保持 `x64`。

| 课堂运行 | 屏幕上确认的结果 |
| --- | --- |
| Debug | 调试运行库弹出 `Buffer is too small` 断言。后来即使注册了回调，07:34 仍出现断言，与讲师起初预期不同。Debug CRT 可以先报告断言，再调用参数处理函数。 |
| Release，使用默认处理函数 | 控制台没有打印复制结果或错误码，进程以非零状态结束。08:55 讲师注释掉回调注册后，再次看到这一现象。 |
| Release，注册自定义处理函数 | 回调先输出诊断，函数名、文件和表达式均显示 `(null)`，行号为 `0`。回调返回后，调用者读到 `strcpy_s` 的返回值并打印 `Error copying string. Error code: 34`。`main` 最后返回 `0`，这个进程退出码和复制是否成功是两回事。 |

代码用 `_set_invalid_parameter_handler(my_invalid_parm_handler)` 注册回调。回调的参数可接收表达式、函数名、文件名、行号及一个保留参数；本次 Release 没有提供可定位到源码的诊断文本。比较错误时应使用 `ERANGE`，`34` 是课堂环境显示的数值。最后恢复了注册代码，本节没有再运行一次容量足够的复制。[Microsoft Learn：注册参数处理函数](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/reference/set-invalid-parameter-handler-set-thread-local-invalid-parameter-handler?view=msvc-170) · [Microsoft Learn：`strcpy_s` 返回值](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/reference/strcpy-s-wcscpy-s-mbscpy-s?view=msvc-170)

日常复制先保证目标至少有 `strlen(src) + 1` 个元素，并把目标的真实容量传给 `strcpy_s`。函数返回 `0` 才读取并使用复制结果。讲师把回调列为选修内容，初学者可先练上一节的正常复制。[P13 字符串复制](013-strcpy_s的用法.md)
