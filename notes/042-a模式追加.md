# P42 用 a 模式追加日志

日志要保留旧记录，并把新消息接到末尾。用 `fopen_s(&file_ptr, filename, "a")` 打开，已有文件会保留，文件不存在时会尝试新建。即使调整过流的位置，下一次写入仍落在文件末尾。文件名中的父目录须存在并允许写入。[Microsoft Learn 的文件打开模式说明](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/reference/fopen-s-wfopen-s?view=msvc-170)

| 需求 | 打开模式 | 对已有内容的影响 |
| --- | --- | --- |
| 只写日志，每次加在末尾 | `"a"` | 保留，写入始终追加 |
| 还要读取日志，写时仍追加 | `"a+"` | 保留，文件不存在时可新建 |
| 从头生成输出文件 | `"w"`，需要同时读取则用 `"w+"` | 打开成功时清空原内容 |
| 修改已有文件指定位置 | `"r+"` | 保留原内容，文件必须已存在 |

## 从函数调用到文件验证

讲师把日志写入封装成 `void append_log_safe(const char *filename, const char *msg)`。调用者给出日志路径和消息，函数以 `"a"` 模式打开，检查结果，然后执行 `fprintf(file_ptr, "%s\n", msg);` 并关闭文件。这里的换行来自格式字符串，每次写入后下一条记录才会另起一行。整理者补充，若要向调用者报告写入成功，要同时检查 `fprintf` 的返回值非负、`fclose` 的返回值为 0，关闭时仍可能遇到缓冲数据写出失败。

首次运行先调用了读取配置的函数。路径漏写 `Users`，程序报告找不到配置文件，尚未执行追加。修正路径后，桌面上出现 `log.txt`。讲师用记事本打开，看到首条 `select * from students`；改消息为 `drop`，再运行后旧行仍在，新行出现在下方。这两串文字只是日志内容。10:48 左右最后一次打开文件，首条仍在，下面已有三行 `drop`，显示重复运行会继续追加。

片尾还调用微软的 `_fcloseall()`，打印本次额外关闭的流数为 0。它会尝试关闭该运行库仍打开的文件流，保留 `stdin`、`stdout` 和 `stderr`。在自己打开流的函数里逐一检查 `fclose`，可以准确知道哪一次写日志失败。[Microsoft Learn 的 fclose 与 _fcloseall 文档](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/reference/fclose-fcloseall?view=msvc-170)
